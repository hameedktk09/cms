⚙️ Institution, Event & Data Source Setup

⚡ Quick start — auto-detect your files from GitHub
Paste a public GitHub repository or folder link. The app lists the files and matches them by name: Participants / Organisers / Speakers / Check-in / On-Site sheets, certificate PDFs (Participant, Organizer, Speakers), Program Flow PDF, logos & banner, and the event title.
📋 Form links (for the QR codes)
Reads the folder “Google Form Links” — Feedback, Pre-registration, Check-in and On-Site Registration links — and fills the form fields below. Works with .txt, .url, .webloc, .json or .md files (one file with lines like “Feedback form link: https://…”, or one file per form). GitHub detection above also reads this folder.

1. Institution / Event Identity

2. Live Data Sources — Google Forms responses & others

Google Forms: open the form → Responses → Link to Sheets → in the sheet click Share → Anyone with the link: Viewer → paste that sheet link here (a forms.gle link only fills the form, it can’t be read). Published-to-web CSV links, GitHub raw CSVs, direct .csv / .xlsx URLs also work. Tick Present for check-in / on-site / organiser sheets (everybody in them is marked present automatically).

3. Form Links (QR codes are generated from these)

Optional prefill: put {name} or {email} in the link (e.g. …viewform?entry.123={name}). Otherwise ?id=name is appended.

4. Certificate Templates (PDF, PNG or JPG) & Name Placement

On: registered people who were never checked in cannot download a certificate. Check-ins come from the desk, quick check-in, or a source marked “check-in”. Off: everyone registered can download.
Nothing is loaded automatically — set a URL / file name, or upload a file. Uploaded templates stay in this browser only; for the public participant portal use a URL or a file hosted next to this page. Use Test in the E-Certificate view to preview the name position.
